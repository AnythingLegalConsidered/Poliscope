  <action>
    Rewrite `search.get.ts` to return both interventions AND scrutins matching the query.

    **Approach: SQL UNION ALL with subquery wrapper** (per research Pitfall 4 — count(*) OVER() must wrap the entire UNION, not be inside each branch).

    The query structure:
    ```sql
    SELECT *, count(*) OVER() AS total_count FROM (
      -- Branch 1: interventions (existing logic)
      SELECT
        'intervention' AS type,
        i.id,
        ts_rank(i.search_vector, websearch_to_tsquery('french', $q)) AS rank,
        ts_headline('french', i.content, websearch_to_tsquery('french', $q),
          'StartSel=<mark>, StopSel=</mark>, MaxWords=35, MinWords=15, MaxFragments=2, FragmentDelimiter= ... ') AS highlight,
        i.speaker_name AS speaker_name,
        d.id AS context_id,
        d.title AS context_title,
        d.date AS context_date,
        dep.id AS actor_id,
        dep.full_name AS actor_name,
        dep.political_group AS actor_group,
        dep.photo_url AS actor_photo,
        NULL::text AS result,
        NULL::integer AS votes_for,
        NULL::integer AS votes_against,
        NULL::integer AS votes_abstain,
        d.chamber AS chamber
      FROM interventions i
      LEFT JOIN debates d ON i.debate_id = d.id
      LEFT JOIN actors dep ON i.actor_id = dep.id
      WHERE i.search_vector @@ websearch_to_tsquery('french', $q)

      UNION ALL

      -- Branch 2: scrutins (NEW)
      SELECT
        'scrutin' AS type,
        s.id,
        ts_rank(to_tsvector('french', s.title), websearch_to_tsquery('french', $q)) AS rank,
        ts_headline('french', s.title, websearch_to_tsquery('french', $q),
          'StartSel=<mark>, StopSel=</mark>, MaxWords=35, MinWords=15, MaxFragments=1') AS highlight,
        NULL AS speaker_name,
        s.id AS context_id,
        s.title AS context_title,
        s.date AS context_date,
        NULL AS actor_id,
        NULL AS actor_name,
        NULL AS actor_group,
        NULL AS actor_photo,
        s.result AS result,
        s.votes_for AS votes_for,
        s.votes_against AS votes_against,
        s.votes_abstain AS votes_abstain,
        s.chamber AS chamber
      FROM scrutins s
      WHERE to_tsvector('french', s.title) @@ websearch_to_tsquery('french', $q)
    ) sub
    ORDER BY rank DESC, id DESC
    LIMIT $limit OFFSET $offset
    ```

    Use `to_tsvector` at query time for scrutins (no stored search_vector needed for 7k rows — per research decision).

    **Use `i.search_vector` (stored column)** for interventions instead of the current `to_tsvector('french', i.content)` — the stored column exists and is indexed, so this is a performance improvement.

    **Keep existing filters (deputyId, debateId, tag) on the interventions branch only** — they don't apply to scrutins. Add a new optional `type` query param to filter results to only 'intervention' or 'scrutin'.

    **Add optional `chamber` query param** to filter both branches by chamber.

    **Response format:** Each result object has a `type` field ('intervention' | 'scrutin') plus type-specific fields. For interventions, keep backward-compat field names (speakerName, debate, deputy, tags). For scrutins, return: type, id, rank, highlight, title (context_title), date (context_date), result, votesFor, votesAgainst, votesAbstain, chamber.

    Map the raw SQL rows to a clean response format:
    - For type === 'intervention': return same format as current search (backward compat) with added `type: 'intervention'`
    - For type === 'scrutin': return `{ type: 'scrutin', id, rank, highlight, title, date, result, votesFor, votesAgainst, votesAbstain, chamber }`

    NOTE: Tags subquery for interventions should be done as a batch after the main query (like deputies/[id].get.ts does) to avoid per-row subquery in the UNION. OR: keep the correlated subquery inside the interventions branch (it's in the existing code and works). Choose the simpler approach: keep the correlated subquery for interventions tags inside the UNION is complex — instead, fetch tags in a second query for the intervention results only.

    Simplification: Do the UNION query first to get results, then batch-fetch tags for intervention-type results only (using their IDs). This avoids embedding a correlated subquery inside the UNION.
