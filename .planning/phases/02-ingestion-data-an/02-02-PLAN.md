  <action>
    Creer `scripts/ingest_debates.py` qui fait l'ingestion en 3 etapes:

    **Etape 1 — Charger le cache des deputes en memoire:**
    - Query `SELECT id, official_id FROM deputies` au demarrage
    - Construire un dict `{official_id: db_id}` pour le matching rapide
    - Log le nombre de deputes en cache

    **Etape 2 — Recuperer les seances:**
    - GET `{NOSDEPUTES_BASE}/seances/json` avec pagination (`?page=N`). Le JSON retourne une structure avec les seances.
    - Pour chaque page, extraire les seances. Continuer tant que la page retourne des resultats.
    - Filtrer sur `hemicycle` seulement (pas les commissions pour le MVP): ajouter `?type=hemicycle` si l'API le supporte, sinon filtrer cote client.
    - Pour chaque seance:
      - `official_id`: identifiant unique de la seance (champ `id` ou `seance_id` de l'API)
      - `title`: generer un titre depuis la date et le type ("Seance du {date}" ou le titre de l'API si dispo)
      - `date`: parser la date au format ISO
      - `legislature`: 17
      - `session_type`: "hemicycle" ou le type retourne par l'API
      - `source_url`: URL nosdeputes.fr de la seance
    - **Incrementalite**: Avant de traiter une seance, verifier si son `official_id` existe deja en DB. Si oui, skip (sauf si on veut mettre a jour). Utiliser upsert INSERT ON CONFLICT (official_id) DO UPDATE.

    **Etape 3 — Recuperer les interventions de chaque seance:**
    - Pour chaque seance inseree, GET `{NOSDEPUTES_BASE}/seance/{seance_id}/json`
    - Le JSON retourne les interventions avec: `intervenant` (ou `intervention.personnalite`), `contenu`, `timestamp`, etc.
    - **IMPORTANT**: Explorer la structure JSON reelle au runtime. L'API nosdeputes.fr n'est pas parfaitement documentee. Logger la structure du premier resultat pour debug.
    - Pour chaque intervention:
      - `debate_id`: l'id DB de la seance parente (pas l'official_id, l'id auto-incremente)
      - `deputy_id`: chercher le depute via son identifiant dans le cache. Si non trouve, laisser NULL.
      - `speaker_name`: nom complet de l'intervenant
      - `speaker_role`: role si dispo ("president", "ministre", etc.)
      - `content`: texte complet de l'intervention. Nettoyer le HTML si present (strip tags).
      - `order_in_debate`: index sequentiel (1, 2, 3...) dans la seance
    - Upsert: comme il n'y a pas d'official_id sur interventions, utiliser la combinaison (debate_id, order_in_debate) comme contrainte d'unicite pour l'idempotence. **OU** inserer seulement si le debate_id n'a pas encore d'interventions en DB.
    - Committer par seance (pas par intervention) pour la performance.
    - Rate limiting: 1 req/sec entre chaque appel API.
    - Afficher une barre de progression avec tqdm.

    **Gestion d'erreurs:**
    - Si une seance echoue (erreur API, parsing), logger l'erreur et continuer avec la suivante.
    - Ne pas crasher le pipeline entier pour une seance problematique.
    - A la fin, afficher un resume: X seances traitees, Y interventions inserees, Z erreurs.

    **Scope initial:**
    - Pour eviter un script qui tourne des heures, ajouter une option `--limit N` (argparse) qui limite le nombre de seances traitees. Default: toutes.
    - Ajouter aussi `--start-date YYYY-MM-DD` et `--end-date YYYY-MM-DD` pour filtrer par date.

    **Note sur la structure JSON de nosdeputes.fr:**
    La structure exacte des endpoints seances/interventions peut varier. Le script DOIT:
    1. Logger la structure JSON brute du premier resultat (json.dumps avec indent)
    2. Etre defensif avec `.get()` partout
    3. Avoir un mode `--dry-run` qui fetch et affiche sans inserer
