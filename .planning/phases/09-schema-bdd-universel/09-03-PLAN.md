Two edits in `packages/shared/drizzle/0001_rename-deputies-to-actors.sql`:

1. **Line 41**: Change `idx_interventions_fts_stored` to `idx_interventions_fts` — this aligns the SQL with what schema.ts (line 58) and 0001_snapshot.json (line 474) already declare.

   Before: `CREATE INDEX "idx_interventions_fts_stored" ON "interventions" USING gin ("search_vector");`
   After:  `CREATE INDEX "idx_interventions_fts" ON "interventions" USING gin ("search_vector");`

2. **Line 44**: DELETE the line `DROP INDEX IF EXISTS "idx_interventions_fts";` entirely. This line was intended to drop the OLD functional index, but since we now name the NEW index `idx_interventions_fts`, it would immediately drop the index we just created. The old functional index (if any) used the same name, so the CREATE INDEX on line 41 will implicitly replace it (or fail if it exists — in which case add a DROP before the CREATE, targeting the old index, but name the new one identically). Actually: PostgreSQL CREATE INDEX does NOT replace. So the correct approach is:

   - Keep a DROP before CREATE but rename so the flow is:
     ```sql
     DROP INDEX IF EXISTS "idx_interventions_fts";
     CREATE INDEX "idx_interventions_fts" ON "interventions" USING gin ("search_vector");
     ```
   - This drops the old functional index first, then creates the new stored-column GIN index with the SAME name.

   So the final corrected lines 40-44 should be:
   ```sql
   -- Drop old functional GIN index (replaced by stored column index below)
   DROP INDEX IF EXISTS "idx_interventions_fts";

   -- Create GIN index on interventions search_vector (stored version)
   CREATE INDEX "idx_interventions_fts" ON "interventions" USING gin ("search_vector");
   ```

   Note: The DROP must come BEFORE the CREATE (swap current line order: lines 43-44 move before lines 40-41).

**DO NOT** modify `meta/0001_snapshot.json` — it already declares `idx_interventions_fts` which is correct.
**DO NOT** modify `schema.ts` — it already declares `idx_interventions_fts` which is correct.
